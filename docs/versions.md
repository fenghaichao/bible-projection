# 译本清单与版权

本项目支持 **7 个中文圣经译本**：

- 和合本（简体）、和合本（繁体）、吕振中译本——**均属公有领域**，**随程序分发**，装好即可用；
- 和合本修订版 2010、中文标准译本、现代中文译本 2019、环球新译本——
  **仍受版权保护**，**不随程序分发、也不在本仓库内**，由使用者自行下载或导入，
  下载前程序会先要求确认使用者已自行取得使用授权。

> 受版权保护的译本如果被打包进公开仓库，等同于替权利人做再分发，风险很高。
> 因此本仓库只保留**公有领域**的 3 个译本，其余 4 个译本只提供**获取入口**：
> 应用内「获取译本」面板的在线下载（数据来自信望愛 FHL API），或从本地 JSON 文件导入。
> 使用者**须自行确认并取得使用授权**，详见[第二节](#二版权与合规说明)。

> 数据流与 IPC 契约见 [架构说明 · 多译本架构](architecture.md#8-多译本架构)。

## 一、译本清单

清单文件是仓库内的 `data/versions/manifest.json`，格式为 `{"versions": [ ... ]}`，
每个条目描述一个译本。

| id | 名称 | 是否内置 | 版权归属 | 来源 |
| --- | --- | --- | --- | --- |
| `simplified` | 和合本（简体） | ✅ 内置 `data/bible-simplified.json` | 公有领域（1919 年中文和合本） | 原版《语音投影圣经》Access 数据库 `bibleNosound.dat` |
| `traditional` | 和合本（繁体） | ✅ 内置 `data/bible-traditional.json` | 公有领域（1919 年中文和合本） | 同上 |
| `lcc` | 吕振中译本 | ✅ 内置 `data/versions/lcc.json` | 公有领域（依 FHL 版权说明页，已超过中国著作权保护期 50 年） | 信望愛 FHL API |
| `rcuv` | 和合本修订版 2010 | ❌ 按需下载（需授权确认） | © 香港圣经公会 | 信望愛 FHL API |
| `csb` | 中文标准译本 | ❌ 按需下载（需授权确认） | © 全球圣经促进会 GBI | 信望愛 FHL API |
| `tcv2019` | 现代中文译本 2019 | ❌ 按需下载（需授权确认） | © 联合国圣经翻译中文委员会 | 信望愛 FHL API |
| `ncv` | 环球新译本 | ❌ 按需下载（需授权确认） | © 环球圣经公会 | 信望愛 FHL API |

数据来源 API：<https://bible.fhl.net/api/qb.php>（信望愛資訊中心）。
节数差异见 [2.4 译本之间的分节差异](#24-译本之间的分节差异)。

### 清单条目字段

| 字段 | 含义 |
| --- | --- |
| `id` | 译本标识，同时也是 `settings.version` 的取值 |
| `name` | 下拉框与界面上的显示名 |
| `bundled` | `true` = 正文随仓库与安装包分发；`false` = 正文不随仓库分发，需自行下载或导入。**当前 3 个条目为 `true`**（和合本简 / 繁、吕振中） |
| `file` | 正文文件名，相对 `data/` 目录。**仅 `bundled: true` 的条目才有此字段**：和合本简 / 繁为 `bible-simplified.json` / `bible-traditional.json`（在 `data/` 根），吕振中为 `lcc.json`（在 `data/versions/`）；`bundled: false` 的条目没有 `file` |
| `fhlVersion` | 信望愛 API 的版本参数，用于在线下载；和合本无此字段 |
| `offlineDownload` | 是否开放离线下载授权，对应信望愛 `abv.php` 的 `candownload`。`false` 时界面加**「需授权确认」**标签，下载前弹确认框；和合本无此字段（默认视为 `true`） |
| `copyright` | 版权归属，界面与本文档都会显示 |
| `source` | 正文来源，界面与本文档都会显示 |
| `lang` | 语言标记，如 `zh-Hans` / `zh-Hant` |

> 内置文件的位置有两种：`data/<file>` 与 `data/versions/<file>`，
> 主进程 `resolveVersionFile()` 两种都会尝试（见 `src/main/versions.js`）。

## 二、版权与合规说明

### 2.1 内置的 3 个译本：公有领域，随程序分发

| 译本 | 权利状态（依 FHL 版权说明页） | 内置文件 |
| --- | --- | --- |
| 和合本（简体 / 繁体） | 1919 年出版，已超过中国著作权保护期 50 年 → 公有领域 | `data/bible-simplified.json`、`data/bible-traditional.json` |
| 吕振中译本 `lcc` | 1952 年《新约新译修稿》、1970 年出版全书，已超过中国著作权保护期 50 年 → 公有领域 | `data/versions/lcc.json` |

- **和合本**（Chinese Union Version, 1919）的版权**已过期进入公有领域**，
  因此其正文（简体与繁体）随仓库与安装包一起分发，可自由使用与再分发。
  仓库内的两份正文来自原程序《语音投影圣经》数据库的抽取结果，详见 [数据说明](data.md)。
- **吕振中译本**：信望愛版权说明页（<https://www.fhl.net/main/fhl/fhl8.html>）记载，
  该译本 1952 年由香港圣书公会出版《新约新译修稿》、1970 年正式出版全书，
  **已超过中国著作权保护期 50 年，属公有领域**；FHL 模块清单 `abv.php` 中它的
  `candownload` 标记为 `1`（开放离线下载授权）。因此其正文（31,081 节，3,967,569 字节）
  **随仓库与安装包一起分发**。
  这也让 `data/` 目录从约 7.2 MB 增加到约 11.2 MB，仓库与安装包相应增大约 4 MB。

### 2.2 需要按需下载的 4 个译本：受版权保护，不随程序分发

| 译本 | 权利人 |
| --- | --- |
| 和合本修订版 2010 `rcuv` | © 香港圣经公会 |
| 中文标准译本 `csb` | © 全球圣经促进会 GBI |
| 现代中文译本 2019 `tcv2019` | © 联合国圣经翻译中文委员会 |
| 环球新译本 `ncv` | © 环球圣经公会 |

- 这 4 个译本的正文**受版权保护**，版权归上表所列机构所有；
- **本仓库与安装包都不含这 4 个译本的正文**，也不提供镜像、压缩包或直链；
- 数据的原始来源是**信望愛 FHL API**（<https://bible.fhl.net/api/qb.php>），
  `tools/fetch-versions.py` 只是一个**从公开 API 抓取并转换格式**的辅助脚本；
- 两种获取方式（详见[第四节](#四获取译本)）：
  1. **应用内下载**：顶栏「获取译本」面板 →「下载安装」，下载的文件只写入本机
     `%APPDATA%\BibleProjection\versions\`；
  2. **从本地文件导入**：导入一个 `[书卷号, 章, 节, 正文]` 数组格式的 JSON 文件；
- **下载并使用即表示你已自行取得使用授权**——本项目不代替使用者判断授权，
  也不替你承担侵权责任。请先阅读下一节的版权声明。

### 2.4 译本之间的分节差异

各译本**分节不同**（31,061 – 31,102 节）。这是译本本身的差异，不是数据损坏。
因此应用**不跨译本用节号定位经文**：历史、收藏与标注只记录「卷:章:节」的位置，
正文按当前译本取回。

## 三、译本数据的存放位置

| 类别 | 路径 | 是否进 Git |
| --- | --- | --- |
| 译本清单 | `data/versions/manifest.json` | ✅ 进仓库（只含元信息，不含正文） |
| 内置和合本正文 | `data/bible-simplified.json`、`data/bible-traditional.json` | ✅ 进仓库（公有领域） |
| 内置吕振中正文 | `data/versions/lcc.json` | ✅ 进仓库（公有领域） |
| 受版权译本正文 | — | ❌ **不在仓库内**，需自行下载到用户目录 |
| 用户下载 / 导入的译本正文 | `%APPDATA%\BibleProjection\versions\<id>.json` | ❌ 不进仓库（用户数据目录） |
| 上述译本的元信息 | `%APPDATA%\BibleProjection\versions\<id>.meta.json` | ❌ 不进仓库 |

> `%APPDATA%` 在 Windows 上对应 `C:\Users\<用户名>\AppData\Roaming`，
> 与 Electron 的 `app.getPath('userData')` 指向同一处（应用目录名为 `BibleProjection`）。
> 卸载应用不会自动删除这里的译本文件。

**查找顺序**：内置优先，其次用户目录（见 `src/main/versions.js` 的 `resolveVersionFile()`）。
清单里没有、但用户目录里存在的译本（例如手工导入的），会在译本列表里以「本地导入」呈现。

### 译本文件格式

内置译本与用户安装的译本**同构**，即一个扁平数组：

```json
[[1, 1, 1, "起初神创造天地。"], [1, 1, 2, "地是混沌、地是空虚。"]]
```

每个元素是 `[书卷号, 章, 节, 经文正文]`，书卷号 1–66 对应 `src/shared/books.js` 里的卷序。
用户目录下的译本还配套一个 `<id>.meta.json`，记录该译本的元信息：

```json
{
  "id": "rcuv",
  "name": "和合本修订版 2010",
  "fhlVersion": "rcuv",
  "verses": 31094,
  "copyright": "© 香港圣经公会",
  "source": "信望愛資訊中心 FHL API（https://bible.fhl.net/api/qb.php）",
  "installedAt": "2026-01-01T00:00:00.000Z"
}
```

## 四、获取译本

### 4.1 应用内下载 / 导入

顶栏有两个相关控件：

- **译本下拉框**（`#version-select`）：列出全部 7 个译本。和合本简 / 繁与吕振中随程序分发，
  选中即切换；其余 4 个需要先下载或导入，未安装时显示「XXX（未安装）」，
  此时选中**不会切换**，只会提示到「获取译本」面板处理。
- **「获取译本」按钮**（`#btn-versions`）：打开右侧抽屉里的「获取译本」面板。

「获取译本」面板里，每个译本一行，显示名称、状态标签、来源与版权：

| 状态 | 按钮 | 说明 |
| --- | --- | --- |
| 内置（和合本简 / 繁、吕振中） | 「使用此译本」 | 当前译本显示「当前译本」并禁用；点击即切换 |
| 已安装（用户导入 / 下载） | 「使用此译本」 | 同上 |
| 未安装（文件缺失） | 「下载安装」 | 下载中显示进度条与百分比，进度条下方提示「下载即从信望愛 FHL 逐卷取得该译本正文并存入本机，请自行确认使用授权。」，并可「停止跟踪」（只停止界面跟随，后台下载可能仍在继续）；下载完成后自动切换到该译本 |
| 未安装 + **需授权确认**（4 个受版权译本） | 「下载安装」 | 点击后先弹确认框（写明版权方、FHL 未开放离线下载授权、仅供个人使用、需自行取得授权）；**取消则不下载** |
| 任意 | 面板底部「从本地文件导入…」 | 导入本地译本 JSON，文件格式与内置译本相同（`[书卷号, 章, 节, 正文]` 数组），译本 id 取文件名（去 `.json`） |
| 任意 | 面板底部「刷新列表」 | 重新读取译本清单与安装状态 |

下载过程中主进程通过 `bible:version-progress` 事件推送进度；
安装或导入成功后广播 `bible:versions-changed`，界面刷新列表并**自动切换到刚装好的译本**。

面板底部有版权提示：**译本正文版权归各译本权利人所有；本程序不随附受版权保护的译本，
只提供下载入口（数据来自信望愛 FHL）；下载并使用即表示你已自行取得使用授权。导入的译本仅在本机使用。**

> **顶栏没有独立的「简 / 繁」按钮**：繁体经文请在译本下拉框里选「和合本（繁体）」。

### 4.2 命令行：抓取 / 清洗 / 校验

仓库自带抓取脚本 `tools/fetch-versions.py`（Python 3 + 网络）：

```bash
# 抓取全部 4 个可下载译本到 %APPDATA%\BibleProjection\versions
python tools/fetch-versions.py

# 只抓指定译本
python tools/fetch-versions.py --versions rcuv,csb

# 抓取到指定目录
python tools/fetch-versions.py --versions ncv --out D:\vers
```

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `--versions` | 全部 4 个 | 逗号分隔的译本 id（`rcuv` / `csb` / `tcv2019` / `ncv`） |
| `--out` | `%APPDATA%\BibleProjection\versions` | 输出目录 |
| `--workers` | `6` | 并发线程数 |
| `--delay` | `0.12` | 每次请求之间的间隔（秒），避免给公开 API 造成压力 |

脚本会逐卷抓取 66 卷经文，写出 `<id>.json` 与配套的 `<id>.meta.json`；
输出目录默认就是应用读取的用户译本目录，抓完即可在应用里使用。

> 该脚本需要 Python 3 与网络连接，**属于用户侧取数工具，不参与 CI**。

### 4.3 多版本对比（逐节对照）

「获取译本」面板底部有**「多版本对比」**区块：把**同一节经文**按多个译本逐个列出，便于逐词对照。
**不做左右分栏**——正文仍是单栏，每一节下面依次列出各译本的那一节。

操作步骤：

1. 打开顶栏「获取译本」按钮 → 面板底部「多版本对比」；
2. 点选 **2–4 个已安装译本**（chip 按钮，选中后高亮；未安装的译本置灰不可选；选中不足 2 个时「对比当前经文」按钮禁用）；
3. 点「对比当前经文」（点完面板自动关闭，正文切换为对照显示）。

行为约定：

| 项 | 说明 |
| --- | --- |
| 正文布局 | 单栏。每一节（节号在左）下面依次列出所选译本的同一节正文 |
| 每条标签 | 「译本名 章:节」小字标签，例如「吕振中译本 1:1」 |
| 顺序 | 与勾选顺序一致（勾选顺序即 panel 里的 chip 顺序：和合本（简体）、吕振中译本、和合本修订版 2010 …） |
| 翻节 / 换章 | 对照保持生效，自动重新取各译本的新章节正文 |
| 结束 | 面板里的「结束对比」按钮（同时清空勾选）恢复单译本显示 |
| 与原版「多栏对照」的关系 | 原版的「对照栏」功能本版**没有实现**（2026-11-11 按用户要求移除）；需要并排比较时用本节的「多版本对比」 |

实现要点：对照取数走 `bible:getChapter` 的**可选第三参 `version`**（省略＝当前译本），
数据缓存在 `state.compare.texts[译本id][章][节]`；渲染由 `stage.js` 的 `verseNode()` 负责，
对比开启时每节生成 `.verse-compare-row`（含 `.verse-compare-label` 与 `.verse-compare-text`），
关闭时回到普通的 `.verse-text`（含关键字高亮）。

> **各译本分节并不一致**（31,061 – 31,102 节），同一节号在个别译本中可能不存在或内容不同；
> 对照时以各译本自身的分节为准。

## 五、校验与清洗

| 脚本 | 作用 | 是否联网 |
| --- | --- | --- |
| `tools/verify-data.js` | 校验**内置和合本**的节数、键唯一性与简繁一致性 | ❌ 不联网 |
| `tools/verify-versions.js` | 校验译本文件的结构与内容：JSON 可解析、每行是 `[书卷号, 章, 节, 正文]`、行序按 `(书卷号, 章, 节)` 升序、键不重复、每章节号连续、文本非空、每卷节数与和合本基准比对、与和合本的键集合差异，并抽查创世记 1:1、约翰福音 3:16、箴言 3:5、启示录 22:21；同时校验 `data/versions/manifest.json` 的字段完整性 | ❌ 不联网 |
| `tools/clean-versions.js` | 对译本文件做一次清洗（去 HTML 标签与实体、行内注释、脚注编号 `【14】`、节内换行），清洗规则与 `src/main/versions.js` 的 `cleanText` 一致 | ❌ 不联网 |

常用用法：

```bash
node tools/verify-versions.js data/versions    # 校验仓库内的清单 + 内置和合本
node tools/verify-versions.js                  # 校验仓库内置数据 + 默认用户译本目录
node tools/verify-versions.js D:\vers          # 校验指定目录下的译本
node tools/verify-versions.js D:\vers --strict # 节数与和合本不一致也判 FAIL

node tools/clean-versions.js                   # 清洗默认用户译本目录
node tools/clean-versions.js D:\vers           # 清洗指定目录
```

> ℹ️ `tools/clean-versions.js` 会遍历目录下所有 `.json` 文件，
> 现在已**自动跳过 `manifest.json`**，因此可以直接对 `data/versions/` 运行，不会中断
> （实测：`lcc.json: 31081 行，修正 0 行，丢弃空节 0 行`——内置文件已经是干净数据）。
>
> ℹ️ `tools/verify-versions.js --repo-only` 的语义为「**只校验仓库内置数据**」，
> 即只检查 `data/` 下随仓库分发的和合本简 / 繁与吕振中三个文件；
> 不带该参数则校验用户译本目录（`%APPDATA%\BibleProjection\versions`）。
>
> ℹ️ 该脚本的「仓库内置文件清单」直接读 `data/versions/manifest.json` 的 `bundled: true` 条目，
> 增删内置译本不需要改脚本；内置文件既可放在 `data/<file>` 也可放在 `data/versions/<file>`。

> 译本之间本来就有分节差异（例如环球新译本比和合本少几十节），
> 这是译本本身的差异而不是数据损坏，因此默认只告警、不判失败；需要严格时加 `--strict`。
>
> 校验与清洗脚本都**只读 / 只改本地文件，不访问网络**；
> 它们目前也**不在 CI 中运行**（CI 只做安装与单元测试）。
